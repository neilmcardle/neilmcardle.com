<Section title="Async and Await">
JavaScript runs fast. The internet runs slow. If you fetch data and wait for the response to come back, your page freezes. The solution: `async` and `await`.

An `async` function returns a promise. Inside it, you can use `await` to pause execution until something finishes, then pick up with the result. No callback hell. No `.then()` chains (though those still work).

```javascript
async function getBook() {
  const response = await fetch('https://api.example.com/books/1');
  const book = await response.json();
  console.log(book.title);
}

getBook();
```

When you call `getBook()`, the first line runs, then pauses at `await`. The page stays responsive. Once the fetch completes, the second `await` runs and parses the JSON. Then `console.log` fires with the book title. It reads like synchronous code, top to bottom, but your page never froze.

</Section>

<Section title="The Fetch API and JSON">
`fetch()` is the modern way to make network requests. It takes a URL and returns a promise that resolves to a Response object. That Response has methods like `.json()` to parse the response body as JSON.

```javascript
const response = await fetch('https://jsonplaceholder.typicode.com/posts/1');
console.log(response.status); // 200
console.log(response.ok);     // true

const post = await response.json();
console.log(post.title);
```

`fetch()` handles the HTTP request for you. You get back a Response with `.status`, `.headers`, `.body`, and more. The `.json()` method reads the response as JSON and parses it into a JavaScript object. Most APIs return JSON, so you will use `.json()` a lot. One gotcha: `fetch()` does not reject on HTTP errors like 404 or 500. `response.ok` tells you if the status was in the 200-299 range. You have to check it yourself.

</Section>

<Section title="Error Handling in Async Code">
Async code can fail. The network dies. The API returns an error. Your code tries to access a property that doesn't exist. You need to catch these problems before they crash your page.

Use try/catch blocks with async/await.

```javascript
async function fetchUserPosts(userId) {
  try {
    const response = await fetch(`https://jsonplaceholder.typicode.com/posts?userId=${userId}`);
    
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}: ${response.statusText}`);
    }
    
    const posts = await response.json();
    return posts;
  } catch (error) {
    console.error('Failed to fetch posts:', error.message);
    return [];
  }
}
```

The `try` block runs your code. If anything throws an error, the `catch` block catches it and handles it. Here we throw an error if the HTTP status is not ok, then catch it and log it. We return an empty array as a fallback so the rest of your app doesn't crash.

</Section>

<Section title="Organizing Code with ES Modules">
As your projects grow, you need to split code across files. ES modules let you export functions and objects from one file and import them in another.

Use `export` at the top level to make things available. Use `import` to bring them in. This is cleaner than passing everything as props, and it scales to large codebases.

An API utility file might have `export async function fetchPost(id) { ... }`. A React component can then import it: `import { fetchPost } from '../utils/api.js'`. The component does not need to know how fetching works. It just calls the function and handles the result.

</Section>

<Section title="Building a Data-Backed Component">
Let's put it together. Build a React component that fetches real data and displays it on the page.

We will use the JSONPlaceholder API, a free fake API perfect for learning. The component will fetch a post and show its title and body.

```javascript
import React, { useState, useEffect } from 'react';

export function PostCard({ postId }) {
  const [post, setPost] = useState(null);
  const [error, setError] = useState(null);
  const [loading, setLoading] = useState(true);
  
  useEffect(() => {
    async function loadPost() {
      try {
        const response = await fetch(`https://jsonplaceholder.typicode.com/posts/${postId}`);
        if (!response.ok) throw new Error('Post not found');
        const data = await response.json();
        setPost(data);
      } catch (err) {
        setError(err.message);
      } finally {
        setLoading(false);
      }
    }
    
    loadPost();
  }, [postId]);
  
  if (loading) return <div className="card">Loading...</div>;
  if (error) return <div className="card error">{error}</div>;
  
  return (
    <div className="card">
      <h2>{post.title}</h2>
      <p>{post.body}</p>
    </div>
  );
}
```

The component uses `useState` to track the post, any error, and a loading flag. `useEffect` runs once on mount to fetch the post. Inside the async function we fetch, check `response.ok`, parse JSON, and set the state. If anything fails, we catch it and set the error. The component renders loading, error, or post data based on the current state. Pass different `postId` values and watch the component re-fetch automatically.

</Section>

<Section title="Thread: Error Location is a Hint">
When async code breaks, the error stack trace tells you exactly where. Pay attention.

If you see an error from inside a `fetch()` call, it is usually a network error: bad URL, server down, or CORS blocked. If you see an error from `.json()`, the response was not valid JSON. If you see an error from accessing a property on the parsed object, the API returned a different shape than you expected.

Most importantly, errors inside a `try` block will be caught by `catch`. Errors outside the try block will crash your page. This is intentional. The error is telling you "your code structure leaked." Move the risky code into the try block. Use error location as a hint to fix your architecture.

</Section>
