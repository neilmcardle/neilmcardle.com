# Mission: Neovim

## Why
Neil wants to replace VS Code with nvim as his primary editor. He works in a Next.js/TypeScript codebase daily and spends long sessions in the terminal. The goal is a fast, keyboard-driven editing environment that doesn't require the mouse — eventually with LSP, file search, and the full workflow a modern editor demands.

## Success looks like
- Open, navigate, edit, and save any file in nvim without thinking
- Move through code faster than he currently can in VS Code
- Use nvim motions to edit text at the level of words, lines, and blocks
- Have a working nvim config with LSP, file fuzzy-find, and syntax highlighting
- Never need to reach for the mouse while editing

## Constraints
- Complete beginner to vim/nvim — has never used it beyond accidental opens
- Primary context: macOS, TypeScript/Next.js codebase
- Learning happens in short sessions alongside active project work

## Out of scope
- Vimscript (Lua config is the modern path)
- Emacs
- Vim plugins that are nvim-incompatible
